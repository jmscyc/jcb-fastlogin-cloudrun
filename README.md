# JCB 悠遊卡自動搶登錄系統 (JCB FastLogin)

專為台灣 JCB 晶緻卡/極緻卡悠遊卡「自動加值 10% 現金回饋」活動打造的本地端全自動/半自動搶登錄與卡片庫管理系統。
針對悠遊卡官方活動登錄網址：`https://ezweb.easycard.com.tw/Event01/JCBMainServlet` (登錄入口：`JCBLoginServlet`)。

---

## 🌟 核心特色與功能

1. **預先管理卡片庫**：
   - 預存多張 JCB 悠遊卡卡號（自訂名稱、信用卡前 6 碼、後 4 碼、悠遊卡 16 碼 PID）。
   - 卡號介面自動隱碼處理保護個資（如 `3568******1234` 與 `0123 **** **** 2345`）。
2. **靈活勾選本次搶登目標**：
   - 在前端首頁勾選本次要搶登的卡片（支援全選 / 單選切換），系統依序或並行處理。
3. **智慧重試與防壅塞機制**：
   - 伺服器回傳「非開放登錄期間」時，依指定頻率（預設 600ms）持續探測。
   - 遇伺服器擁擠或超時（500/502/504/Timeout），自動刷新並維持連線重試。
   - 頁面一旦開放，**毫秒級自動注入卡號**。
4. **人機驗證碼與視窗支援**：
   - 支援「可視化視窗 (Headed)」模式，驗證碼（Google reCAPTCHA / 圖形碼）跳出時可在視窗中手動點選，點完送出後系統自動接管判斷登錄結果。
5. **首頁即時統計看板**：
   - **本次搶登狀態**：即時顯示各卡片本次執行成功、額滿、已登錄或失敗狀態。
   - **今年度累計登錄次數**：依據 JCB 規範自動統計該卡今年累計成功月份次數。
6. **紀錄管理與清除**：
   - 提供「清除本次執行紀錄」一鍵按鈕（便於下梯次搶登）。
   - 提供「重置今年度登錄次數」與「清空所有紀錄」選項。

## 🏛️ 系統架構與模組說明 (Architecture Overview)

本專案採用三層分離架構設計，便於未來 AI 助理或開發者進行擴充與維護：

```
+-------------------------------------------------------------+
|               前端介面層 (Web UI / Presentation)             |
|  - templates/index.html : 儀表板版面配置與 Modal 彈窗        |
|  - static/css/style.css : 響應式現代化排版、狀態標籤樣式      |
|  - static/js/app.js     : 前端卡片 CRUD、長輪詢狀態更新、日誌推播 |
+-------------------------------------------------------------+
                               | REST API (JSON)
                               v
+-------------------------------------------------------------+
|                 後端 API 控制層 (FastAPI Backend)            |
|  - main.py: FastAPI Web 伺服器，定義 /api/cards,           |
|             /api/records, /api/task 等路由控制器與日誌監聽    |
+-------------------------------------------------------------+
               |                               |
               v                               v
+-----------------------------+ +-----------------------------+
|    資料持久層 (Database)     | |   自動化搶登引擎 (Engine)   |
|  - database.py              | |  - login_engine.py          |
|  - SQLite (cards.db)        | |  - Playwright Chromium 核心 |
|  - 卡片庫、登錄歷程、年度統計 | |  - 毫秒級探測、DOM 注入、狀態辨識|
+-----------------------------+ +-----------------------------+
```

### 關鍵檔案清單與責任劃分

| 檔案路徑 | 模組責任 | AI 改版維護指引 |
|---|---|---|
| `main.py` | FastAPI 路由與應用程式入口 | 新增 API 端點、調整請求模型 (Pydantic Models)、修改日誌緩存容量。 |
| `database.py` | SQLite 資料庫操作與統計計算 | 資料庫表綱要 (`cards`, `login_records`, `settings`)、CRUD 邏輯、年度成功次數去重計算。 |
| `login_engine.py` | Playwright 自動化爬蟲引擎 | 官方網頁變動（HTML 選擇器、欄位 ID）、新增 OCR 驗證碼辨識、調整刷新重試頻率。 |
| `templates/index.html` | 前端視圖模板 | 調整網頁版面結構、增加按鈕或設定欄位。 |
| `static/js/app.js` | 前端邏輯與 REST API 呼叫 | 前端互動（勾選、全選、Modal 表單）、定時輪詢 (`startStatusPolling`)。 |
| `static/css/style.css` | UI 視覺樣式 | 調整配色、終端機黑底樣式、表格欄寬與動畫。 |
| `run.sh` | 本地端一鍵啟動腳本 | 環境檢查、依賴安裝與啟動 uvicorn。 |

## 🛠️ 開發與改版擴充指引 (For Future AI & Developers)

若未來因悠遊卡官方改版或需求變更需要修改程式碼，請依循以下情境：

### 1. 官方網頁欄位或 HTML 結構變更
- **位置**：`login_engine.py` 中的 `_process_single_card()` 與 `_fill_and_submit()`。
- **作法**：
  - 若官方修改了卡號輸入框的 `name` 或 `id`，更新 `fill_script` 中的 `querySelector` 條件。
  - 目前相容欄位包括：`txtCreditCard1`, `txtCard1`, `txtEasyCard1~4`, `txtEasyCard`。
  - 若登錄結果提示文字改變（例如「登錄成功」、「已額滿」、「本月份已登錄」），修改字串匹配條件。

### 2. 整合自動辨識圖形驗證碼 / OCR
- **位置**：`login_engine.py` 中的 `_fill_and_submit()`。
- **作法**：
  - 定位驗證碼圖片元素（如 `img#captcha` 或 `iframe[src*="captcha"]`）。
  - 使用 `page.locator(...).screenshot()` 截圖並送入 OCR 套件（例如 `ddddocr` 或雲端辨識 API）。
  - 將辨識出的字串填入對應的 `input#captcha` 欄位並觸發提交。

### 3. 資料庫結構升級或遷移
- **位置**：`database.py` 中的 `init_db()`。
- **作法**：
  - 若新增卡片欄位（如「發卡銀行」、「卡片備註」），在 `CREATE TABLE IF NOT EXISTS cards` 中新增欄位，並更新 `get_cards()` 與 `add_card()` 參數。

## 🚀 快速啟動方式

在專案目錄下執行：

```bash
cd /config/Desktop/BuildWithGemini/jcb-fastlogin
./run.sh
```

或使用 Python 直接執行：
```bash
python3 -m uvicorn main:app --host 0.0.0.0 --port 8088
```

接著在瀏覽器打開：**`http://localhost:8088`** 即可開始使用！

## 📋 建議操作流程（搶登日使用建議）

1. **活動日前**：
   - 點擊「新增卡片」，將名下要搶回饋的 JCB 悠遊卡全數加入。
2. **搶登日（每月 1, 11, 21 日 09:00 前）**：
   - 於 **08:58 分左右** 打開本系統網頁。
   - 勾選本次要搶登的卡片。
   - 瀏覽器模式選擇「可視化視窗 (Headed)」，重試間隔設定為 400 ~ 600 毫秒。
   - 點擊「🚀 立即開始搶登」。
3. **開放瞬間 (09:00:00)**：
   - 系統自動以毫秒級監測到網頁開放，並自動將卡號填入表單。
   - 視窗若出現「我不是機器人」或圖形驗證碼，請快速完成驗證並送出。
   - 送出後系統會自動辨識登錄結果並記錄於資料庫中，更新統計儀表板。
